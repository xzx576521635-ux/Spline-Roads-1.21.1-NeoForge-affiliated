## 备份与构建约定

与主 mod 一致：

1. **每次构建都必须独立备份**，命名为 `splinequickbuild-<mod版本>.jar.qb<N>`，序号递增，**禁止覆盖**旧文件；
2. `mods/` 里只保留一个 `splinequickbuild*.jar`；
3. 构建统一走 `quickbuild/build.ps1`（自动选择下一个 `.qbN`、计算哈希、可选安装 `-Install`）；
4. 每发布一个版本同时留一份**源码备份**：`mods_backup/splinequickbuild-src-<版本>.qb<N>.zip`
   （不含 `build/`、`.gradle/`、`libs/*.jar`）；
5. 主 mod 与附属 mod 的版本互相独立，但必须在记录里写明“当时配套的主 mod 版本”。

## qb13 — `splinequickbuild-0.2.2.jar`（合成配方）

新增 `data/splinequickbuild/recipe/quick_build_tool.json`，**无序合成**：

```
splineroads:road_connector   （道路连接器）
splineroads:endpoint_creator （端点生成器）

              ↓
```

设计理由：工具本身就是「连接器 + 端点放置 + 测距（指南针）」的组合，
材料全部沿用主 mod 已有的配方体系，不引入新物品。

## qb12 — `splinequickbuild-0.2.1.jar`（强制直线开关）

配套主 mod：`splineroads-2.0-straighthook.jar`（v66）

新增：

## qb11 — `splinequickbuild-0.2.0.jar`（引导线跟随真实道路曲线）

需求：蓝线之前只能画直线，而主 mod 实际会按设置生成平滑曲线/圆弧，希望预览也跟着走。

实现：不再自己画直线，而是**调用主 mod 的几何构建**：

```java
RoadGeometry.Node a = 起点（有端点实体则用 entity.constructionNode()）
RoadGeometry.Node b = 终点（无实体则用合成节点，yaw = 玩家当前朝向）
RoadGeometry.Settings s = new Settings(Mode.AUTO, Style.O2_YELLOW, 9.0, 1.0, 0.35, 90.0)
RoadGeometry.Mesh mesh = RoadGeometry.build(a, b, s);
```

- 用 `mesh.samples()` 的中心线画折线（每段再走 5 线加粗）；
- 缓存以“起点方块 + 终点方块”为键，只在终点方块变化时重算；
- 合成终点节点的 yaw 用玩家朝向，和主 mod 放置 `road_node` 时
  `setPlacedBy` 写入 `yaw = player.getYRot()` 的行为一致；
- 任何构建异常（距离过近、超长、几何无解）都会回退成直线，不会崩；
- HUD 增加“曲线长度”，和直线距离并列显示。

注意：预览用的是**默认设置**（AUTO / O2_YELLOW / 宽 9 / 张力 0.35），
因为设置是在第二次右键后的界面里选的；如果你在界面里改成 STRAIGHT/圆弧，
建造结果会按那时选的模式，而预览始终显示默认 AUTO 的曲线。

## qb9 — `splinequickbuild-0.1.8.jar`（文字屏幕夹取 + 蓝线加粗）

用户反馈：qb8 文字又看不到了；蓝线太细。

1. **文字消失**：qb8 把整块文字改成“底边贴锚点向上排”（`top = y − 行数×行高`）。

   偏移量按 `距离 × 0.0018` 缩放，使屏幕宽度随距离保持稳定（约 5px）。

## qb7 — `splinequickbuild-0.1.6.jar`（线尾文字改为屏幕投影）

用户反馈：qb6 开着光影时**只能看到文字的阴影，看不到文字本体**。

原因：世界空间字体（`Font.drawInBatch` + 矩阵）在 Iris 光影管线里渲染不稳定
（`SEE_THROUGH` 完全不显示，`NORMAL` 只剩阴影），继续调参数收益很低。

改法：**不再在世界里画字**，改为：

1. 在 `RenderLevelStageEvent` 里把线尾世界坐标 `clip = Proj * View * (x, y+1.2, z)` 投影到 NDC，
   换算成 GUI 缩放后的屏幕坐标（`labelX/labelY`），`w <= 0` 时视为在相机背后隐藏；
2. 在 `RenderGuiEvent.Post` 里用 `GuiGraphics.drawString` 画三行文字：
   先四向各画一遍黑色描边，再叠白色正文（坡度行用橙色），保证亮地形/曝光下也能看清；
3. 超出屏幕 ±200 像素时跳过绘制。

这样文字走 GUI 层，与光影、DH、方块遮挡全部无关（始终可见），位置仍然钉在线尾。

## qb3 — `splinequickbuild-0.1.2.jar`（预览与建造权限修复）

配套主 mod：`splineroads-2.0-addonhook.jar`（v65）

两个问题：

1. **开着光影时看不到引导线/HUD**：主 mod 把起点写在手持物品的 NBT 里，而
   **服务端修改物品 NBT 不会同步给客户端**（主 mod 自己也不需要客户端 NBT，界面是走数据包打开的）。
   附属 mod 在客户端读 NBT 永远读不到 → `preview()` 返回 null，线和文字都不画。
   修复：改由客户端自己记录起点（`QuickBuildClient.trackClick`，在物品的客户端分支里调用），
   并处理维度切换、Shift+右键取消、生存模式没有端点物品时不进入会话。
2. **点建造提示“请手持道路连接器并确保拥有建设权限”**：`RoadNetwork.usable(...)` 检查的是
   `stack.getItem() instanceof RoadTool`，而附属物品只继承 `Item`。
   修复：主 mod 把 `RoadTool` 的 `final` 去掉；附属 mod 的物品改为 `extends RoadTool`。
   这样建造、端点高亮（`showsNodes`）等所有检查都自动通过，协议层不需要特例。

## qb2 — `splinequickbuild-0.1.1.jar`（端点自动放置修复）

配套主 mod：`splineroads-2.0-varargfix.jar`（v64）

问题：qb1 只把右键转交给主 mod 的连接器，而连接器**只连接已经存在的端点**，
所以右键地面只会提示“右键端点进行连接”，不会自动放置端点。

根因：主 mod 的端点必须先由 `splineroads:road_node` 方块物品摆出来，连接器才认得。

修复：

- `QuickBuildTool` 在目标位置**先执行一次 `road_node` 方块物品的放置**（复用原版 `BlockItem.useOn`
  规则：领地权限、碰撞、可替换方块判断都一致），放置成功后再把这次点击转交给连接器；
- 生存模式每个端点消耗 **1 个 `spline...road_node` 物品**，创造模式豁免；没有物品时提示
  “背包里没有「道路端点」方块，无法放置端点”；
- 若目标位置已经有端点，则不重复放置，直接走原来的连接逻辑。

## qb1 — `splinequickbuild-0.1.0.jar`（MVP，端点无法放置）

配套主 mod：`splineroads-2.0-varargfix.jar`（v64 稳定版）

新增内容：

- 物品 `splinequickbuild:quick_build_tool`（快速建造工具，堆叠 1，不消耗）
  - 加入主 mod 的创造标签 `splineroads:roads`
  - 模型贴图复用 `splineroads:item/endpoint_creator`
- 第一次右键地面：转交主 mod 的 `RoadTool.useOn(...)`，在点击位置放置道路起点节点
- 持有工具且 NBT 中存在 `Start` 时，客户端实时渲染：
  - 起点 → 准星方块（`mc.hitResult` + `RoadTool.endpointAtHit`）的引导线
  - 两端竖直参考线
- HUD（`RenderGuiEvent.Post`）显示：
  - 起点坐标 / 终点坐标
  - 水平位移 `ΔX`、`ΔZ`、直线距离
  - 高差（格）与坡度（%，>12% 变橙）
  - 操作提示
- 第二次右键：主 mod 照常生成草稿并 `RoadNetwork.open(...)` 弹出原版道路配置界面
- `Shift + 右键空气`：清除选择（同样转交主 mod 的 `RoadTool.use`）

实现要点：

- **不修改主 mod**：`RoadTool.useOn` / `RoadTool.use` 均为 public，且选择状态保存在“当前手持物品栈”的 NBT 中，
  附属物品只需构造新的 `UseOnContext` 回调主 mod 即可；
- `UseOnContext#getHitResult()` 是 protected，因此用
  `new BlockHitResult(clickLocation, clickedFace, clickedPos, isInside)` 重建；
- 预览数据全部来自客户端可读的信息（物品 NBT + 方块射线 + `NodeEntity`），不需要新增网络包。

已知限制（MVP）：

- 没有方向锁定，长距离仍可能走偏；
- 工具不消耗；
- 主 mod 的节点高亮（`RoadTool.showsNodes`）只认自己的物品类型，附属物品暂不触发；
- 未处理“关闭界面后重新打开草稿”（主 mod 的 `resume` 逻辑只在 `RoadTool.use` 客户端分支）。
